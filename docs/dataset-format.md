# 双表测评集格式参考

适用于 V1.8.0。设计自己的测评集或转换现有材料时，先按照以下字段制作普通 `.xlsx` 文件，再通过执行器校验。可复制 [入门测试表](../examples/入门测试_6条.xlsx)作为模板。字段名须逐字一致，不能将“评分标准”改成“评分准则”等近义名称。

## 工作表一：全过程执行表

一行代表一条实际要发送的用户消息。以下 11 列全部必需，可调整列的顺序。

| 字段名 | 填写规则 |
| --- | --- |
| 步骤ID | 唯一编号，如 S0001、S0002。S 后为 1—8 位数字且数值大于 0；按数字部分升序执行。S1 与 S0001 视为重复序号。无需另加顺序ID。 |
| 身份ID | 对应真实账号身份，建议 A、B。1—40 个文字、数字、下划线或横线，不能含空格或使用系统保留名。自动行只能属于同一个身份，其他身份用 MANUAL。 |
| 会话ID | 如 M0、T01。身份ID＋会话ID共同定位对话；首次出现新建并命名，再次出现返回原对话，连续出现则继续发送。1—80 个文字、数字、下划线、点或横线，不能含空格、路径字符、尾随点或使用系统保留名。编号不要只靠英文大小写区分。 |
| 消息类型 | 仅 HISTORY 或 QUESTION。HISTORY 为信息输入，QUESTION 为待测问题；两者都从用户侧发送。删除信息的聊天请求也可以是 HISTORY，删除后的检查问题才是 QUESTION。 |
| 问题ID | HISTORY 留空；QUESTION 填唯一问题编号，如 Q-M02-01，与独立问题表精确匹配。不同问题节点不能复用同一问题ID。 |
| 发送内容 | 非空的完整用户原文，保留换行和标点。说明、截图要求等不属于聊天消息时，不要混入此列。每个单元格不超过 32767 字符。 |
| 回复后等待秒数 | 数值型整数 0—604800；从本条完整回复确认后起算，等完再准备下一步。填 30 或 120，不填“30秒”“2分钟”或“随机”。暂停恢复沿用原截止时间。 |
| 执行方式 | AUTO 为自动发送；MANUAL 为人工操作、填写回复或记录跳过。换账号、清理记忆等当前无法自动执行的操作不能伪装成 AUTO。 |
| 实际回答 | 新模板留空；脚本保存回复后回填。不要放参考答案。 |
| 执行状态 | 新模板留空或填“未执行”；执行后由脚本记录，不预填成功或通过。 |
| 异常说明 | 新模板留空；执行中由脚本填写。人工操作要求放可选列“执行约束”。 |

会话切换由编号决定，不另设“新建窗口”指令行。例如 A/M0 → A/T01 → A/M0，第三步返回最初的 M0，不会再新建同名对话。B/M0 属于另一个真实身份，需要人工切换账号；改编号本身不构成账号隔离。

## 工作表二：独立问题表

只收录 QUESTION 节点，一行对应一个唯一问题ID。以下 8 列全部必需；即使没有问题，也保留带表头的工作表。

| 字段名 | 填写规则 |
| --- | --- |
| 问题ID | 与执行表的 QUESTION 一对一，编号和大小写完全相同，不重复、不遗漏、不多出。 |
| 用例ID | 非空，标识所属用例；一个用例可以有多个问题节点，因此用例ID可以重复。 |
| 测评能力 | 非空，说明本问题测什么，如跨会话召回、信息更新或删除后不再使用。 |
| 测试问题 | 与对应执行行的“发送内容”逐字一致，包括空格、换行和标点。 |
| 预期回答要点 | 非空，写应答出的要点或不应泄露的内容；不填入“实际回答”。 |
| 评分标准 | 非空，按本问题写得分条件、关键错误等。依据原方案保留或经设计者确认后制定；脚本不自动评分。 |
| 实际回答 | 新模板留空，脚本按问题ID回填。 |
| 执行状态 | 新模板留空或“未执行”，由脚本回填。 |

全过程保存所有回复，独立问题表集中保留问题回复和评分依据，便于后续人工或 AI 评分。“执行完成”不等于“能力测试通过”。

## 可选列与使用限制

| 工作表 | 可选字段 | 当前支持情况 |
| --- | --- | --- |
| 全过程执行表 | 执行约束 | 人工节点的账号、准备动作、操作方式等文字说明；脚本不会把自然语言约束解释成新的自动动作。 |
| 全过程执行表 | 计时锚点问题ID、距锚点最早秒数、距锚点最晚秒数 | 三列配套用于 MANUAL 节点；锚点须精确引用更早的 QUESTION，时间为非负整数秒且最晚不早于最早。当前 AUTO 节点不支持此类锚点。 |
| 独立问题表 | 步骤ID、身份ID、会话ID | 如添加，对应每个问题都须与执行表一致。 |
| 独立问题表 | 前置问题ID | 多个 ID 用英文分号分隔，须引用更早的问题，不能自引用或循环。字段用于表达依赖和核对编号，不表示脚本会自动评分并判断前置问题是否答对。 |

其他说明列可以保留，但脚本只按已支持的字段执行。需要人工处理的条件应使用 MANUAL 并填写执行约束，不能只在 MD 中说明然后期待自动执行。人工追加且未核验平台消息编号的会话，后续不能盲目安排 AUTO 续写；建议人工会话与后续自动会话分开，例如入门表 H01 与 M0。

第一行须从 A 列起为表头，不加封面标题行，不合并表头或消息单元格。执行输入、题目、预期和评分填写固定值，不用动态公式。输出列建议直接留空；既有问题表的回答、状态关联公式仅在 [依赖与兼容说明](dependencies.md)范围内支持，转换时不要擅自改坏原关联。

文件不超过 20MB，每表最多 10000 数据行、128 列，不使用图片、图表、宏、透视表或外部工作簿链接。当前没有自动切账号、清理记忆、随机间隔或自动评分功能。

## 用 AI 创建或转换测评集的提示词

复制下面整段，并将本格式参考、原始材料及需求一起提供给具备表格处理能力的 AI。新设计时提供场景、能力目标和规模；转换时提供原测评集。AI 自查后，仍需在执行器内完成真实的“校验并预览”。

```text
请依据我提供的《双表测评集格式参考》和材料，为“豆包长期记忆测评执行器 V1.8.0”创建可导入的测评集，或将已有测评集转换为该格式。

我的任务类型：【创建新测评集 / 转换已有测评集】
场景与测评目标：【填写】
预计消息数、问题数及会话安排：【填写；转换时以原材料为准】
账号身份与人工操作要求：【填写】
回复后等待规则：【填写固定秒数，或逐节点说明】
原始材料：【在此粘贴或附上文件；新设计可填写需使用的合成背景】

先核对材料。若发送顺序、账号、会话连续性、等待时长、预期或评分依据等关键信息不足，请集中列出待确认项，再生成可执行版本；不要自行统一设为30秒，也不要把缺失项伪装成已经确定。

一、输出结构
1. 输出普通xlsx，工作表准确命名为“全过程执行表”“独立问题表”。第一行从A列开始为表头，不加封面行、不合并单元格。
2. 全过程执行表必需字段：步骤ID、身份ID、会话ID、消息类型、问题ID、发送内容、回复后等待秒数、执行方式、实际回答、执行状态、异常说明。
3. 独立问题表必需字段：问题ID、用例ID、测评能力、测试问题、预期回答要点、评分标准、实际回答、执行状态。问题的用例ID、能力、题干、预期和评分都必须有明确内容。
4. 新模板两表的实际回答全部留空；执行状态留空或“未执行”；执行表异常说明留空。输出列优先使用普通空白单元格，不新造复杂公式。

二、输入与匹配规则
5. 一行一条用户消息，按真实流程依次分配S0001、S0002等步骤ID，数字序号唯一；不用另建顺序ID。脚本按步骤ID数字部分执行，不能靠表格位置掩盖编号顺序错误。
6. 消息类型只用HISTORY或QUESTION，执行方式只用AUTO或MANUAL；两类消息都是用户侧发送。HISTORY的问题ID留空；QUESTION有唯一问题ID，并与问题表一对一。
7. 问题表“测试问题”与执行表对应的“发送内容”须逐字一致，保留换行、空格和标点；问题ID及可选的步骤/身份/会话字段须精确一致。
8. 同一身份下，同一会话ID表示同一真实对话；首次出现新建，再次出现返回。不要把返回旧会话改成新建同名会话。身份与会话编号不含空白，不使用系统保留名，不靠英文大小写区分编号。
9. AUTO只能属于一个真实账号身份。其他账号、账号切换或清理记忆等当前不支持的自动操作，安排为MANUAL并写明“执行约束”；不要假定脚本会理解说明文字并执行新动作。
10. 等待字段填写数值型整数秒0—604800，从完整回复确认后起算。不要填写“2分钟”、随机规则或新增脚本不识别的等待字段。复杂人工时间窗口需按格式参考的锚点字段表达，并核对其支持范围。
11. 人工会话与后续自动会话尽量分开；不要让未经平台消息编号核验的人工追加对话直接转为AUTO续写。前置问题只能引用更早的问题；脚本不自动判断能力评分是否通过。

三、内容保真与边界
12. 转换已有材料时，保留消息原文、真实顺序、会话归属、等待要求、能力点、预期及评分依据。不要擅自改写题干、删减节点、合并消息或添加聊天内容；确需调整时先列出原因供我确认。
13. 将非聊天说明、环境准备、截图要求等与“发送内容”分开。人工操作要求放执行约束；评分仅放问题表，不发给被测产品。
14. 创建新测评集时可以根据我确认的目标设计合成材料与评分规则，并明确标注为新设计；转换时不能凭空补成原材料已有内容。缺失的重要依据先询问。
15. 不写入模拟的产品实际回答或评分结果，不把历史结果表直接当新模板。输入和题目字段使用固定值；遵守文件、行列、单元格及不支持对象的限制。

四、交付前自查
16. 核对字段齐全、步骤唯一、消息和问题数量、双表一一匹配、题干逐字相同、等待数值、单一自动身份、人工约束及所有输出列为空。
17. 给出简短转换/设计说明，列出总消息数、AUTO/MANUAL数、QUESTION数、身份与会话数、必要的人工节点；转换已有材料时报告与原材料的数量差异和经确认的调整。
18. 有文件生成能力时提供可下载的xlsx；没有时明确说明，并提供两张结构化表或可生成xlsx的脚本，不要声称已经交付可导入文件。未实际调用本执行器校验时，只能说完成规范自查，不能声称已通过执行器校验或真实产品测试。
```

生成文件后，先检查内容是否保真，再打开执行器“选取/校验 → 校验并预览”。有错误时将具体行、列及错误信息交给 AI 修正；人工节点提示不等于校验失败。格式通过仅代表可读取与匹配，测评设计是否合理仍需设计者判断。
