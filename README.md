# 豆包长期记忆测评执行器

读取双工作表 Excel，通过 CDP 在豆包桌面端按会话发送原文，保存完整回复，并生成回填结果副本。Windows 桌面原型，当前版本 **1.8.0**。

本版修复初始状态勾选区被按钮遮挡的问题，并将 Excel 后端替换为可从公共 npm 安装的 **ExcelJS 4.4.0 + JSZip 3.10.1**。无需专用表格运行库、Python 或本机安装 Microsoft Excel。查看结果需要能够打开 xlsx 的软件。

## 第一次使用：下载到跑完测试

流程：**下载并解压 → 安装依赖 → 打开窗口 → 连接豆包 → 选择并校验 Excel → 开始 → 处理人工节点 → 查看结果**。

### 1. 准备环境并安装

建议使用 64 位 Windows 10/11。通常只需安装 Node.js 和豆包桌面版，再运行项目自带安装入口；.NET Framework 先按下面的方法判断是否需要补装。

#### A. 安装 Node.js（两种方式选一种）

方式一：打开 [Node.js 官网下载页](https://nodejs.org/en/download)，选择 LTS 版本的 Windows Installer（.msi），按安装向导完成，保留 npm 和添加到 PATH 的选项。需要 Node.js 22.15 或以上版本。

方式二：在开始菜单搜索并打开“Windows PowerShell”，运行以下命令，按提示完成安装：

```powershell
winget install --id OpenJS.NodeJS.LTS --exact --source winget
```

如果提示找不到 winget，使用官网安装方式即可。此命令只安装 Node.js，项目依赖在后面的“安装依赖.cmd”中安装。

安装完成后关闭原终端，重新打开 PowerShell，分别执行：

```powershell
node --version
npm.cmd --version
```

两条命令都应输出版本号，Node.js 不低于 v22.15.0。已经满足要求的电脑跳过重装。使用 npm.cmd 可以避免 PowerShell 将命令解析为受执行策略限制的 npm.ps1。

#### B. .NET Framework 通常无需另外安装

窗口使用 .NET Framework 4.8。Windows 11 自带相应版本，较新的 Windows 10 也已包含；已有 4.8 或 4.8.1 时直接使用，不要卸载或降级。[微软的 Windows 随附版本说明](https://learn.microsoft.com/en-us/dotnet/framework/install/on-windows-and-server)

想先确认环境，可在 PowerShell 复制整段检查命令。它只读注册表，不会安装或修改系统：

```powershell
$netRelease = (Get-ItemProperty -LiteralPath 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full' -Name Release -ErrorAction SilentlyContinue).Release
if ($netRelease -ge 528040) {
    Write-Output '.NET Framework 4.8 或更高版本已安装，可以继续。'
} else {
    Write-Output '未检测到 .NET Framework 4.8，请按下方官方链接安装后再试。'
}
```

显示“已安装”就继续下一步。仅在检查未满足要求时，打开 [微软 .NET Framework 4.8 下载页](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48)，点击 **Download .NET Framework 4.8 Runtime**，下载后运行安装程序，按向导完成；若提示重启，重启后再运行项目安装入口。若安装程序提示已有相同或更高版本，则无需继续安装。

普通用户不需要为运行窗口安装整套 Visual Studio；这里的 .NET Framework 4.8 与 .NET 8/9 等是不同产品，按上面的链接选择即可。检查阈值依据[微软的版本检测说明](https://learn.microsoft.com/en-us/dotnet/framework/install/how-to-determine-which-versions-are-installed)。

本项目安装时还会调用系统 .NET Framework 目录中的 C# 编译器。仅当出现“未找到 .NET Framework C# 编译器”时，可以检查：

```powershell
Test-Path (Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe')
```

应返回 True。若框架版本已满足但这里返回 False，请保留该结果和安装报错反馈作者，不必反复安装不同版本的 .NET SDK。

#### C. 安装项目并打开窗口

1. 安装豆包桌面版并登录。后续由执行器启动豆包并检查连接。
2. 在 GitHub 仓库点击 **Code → Download ZIP**，解压整个项目到可写目录，例如“文档”中的测试文件夹。要先解压，再运行里面的文件。
3. 确认解压后的同一目录中有 README.md、package.json、安装依赖.cmd、安装依赖.ps1、构建窗口.ps1、执行设置.json，以及 core、ui、examples 等子文件夹。构建窗口.ps1、执行设置.json 应在项目根目录，不能放进 tools 子目录。
4. 双击 **安装依赖.cmd**，等待出现“安装完成”。它按锁文件从 npm 官方注册表安装依赖、验证 Excel 读写，并构建 exe；首次需要联网。如果提示错误，先处理该错误，不把失败当作安装完成。
5. 打开同目录的 **豆包测评执行器V1_1.8.0.exe**。从 GitHub 下载的源码可能没有 exe，安装脚本会生成它；发布包也可能已附带编译好的 exe。日常使用只需打开 exe，不必重复安装。

如希望通过命令行安装：在解压后的项目文件夹中，点击资源管理器地址栏，输入 `powershell` 后回车，再运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\安装依赖.ps1
```

命令中的执行策略只对该次 PowerShell 进程生效，不需要修改系统的全局执行策略。安装成功后，下面的“连接豆包 → 选择测试表 → 开始”步骤与双击安装方式一致。

### 2. 连接豆包

1. 点击 **选择程序**，选中自己电脑上的 `Doubao.exe`，端口默认保留 `9223`。
2. 点击 **启动豆包**，在豆包中完成登录，再点 **检查连接**。
3. 确认显示“已连接”，并核对“当前账号”。连接成功只表示能访问客户端，尚未开始发送。

如果原来已打开的豆包没有启用调试端口，先正常退出豆包，再从执行器点击“启动豆包”。如果已经能检查连接成功，可直接继续。

### 3. 选择附带测试表并开始

1. 点击 **选取/校验 → 选择 Excel**，选择项目里的 [examples/入门测试_6条.xlsx](examples/入门测试_6条.xlsx)。下载整个项目后已经包含此文件，无需另外制作表格或修改代码。
2. 点击 **校验并预览**。预期显示 **6 条消息、5 自动、1 人工、3 个问题、3 个会话**，0 错误。人工节点会有提示，属于正常情况。
3. 点击 **用于本轮执行**，回到主窗口。流程会自动切换到 **Excel测评集 · 技术回归（按表执行）**。检查“待运行文件”确实是入门测试表。
4. 点击 **开始新一轮**，这时才开始向豆包发送。首次测试使用上述 Excel 技术回归模式；默认的旧 B 正式流程是另外一套 54 条流程。

技术回归沿用当前账号，不要求声明正式测评的独立初始状态。该样例仍会在豆包中创建对话、发送测试文字；运行后不会自动删除对话或清空记忆。

Excel 可以放在任意可写目录，通过窗口选择即可。程序直接读取文件内容，结束时将结果副本也放到该文件同目录。

### 4. 第 5 条人工停点怎么处理

前 4 条会自动完成，依次在 M0 连续发送两条、新建 T01、返回 M0。到第 5 条 H01 时，主按钮变为 **处理人工步骤**；这是样例安排的停点。

1. 点击 **处理人工步骤**，阅读窗口里的“发送原文”和“执行约束”。
2. 在同一个豆包测试账号中手动新建独立会话，按表内 H01 要求操作，发送本步原文；不要追加到 M0 或 T01。
3. 等豆包完整回复后，将首次完整回复粘贴到人工窗口，核对实际账号标识并勾选操作确认。
4. 点击 **保存本步并查看下一步**。本步保存后窗口会提示返回主界面；点击 **继续本轮**。
5. 执行器会返回原 M0，自动发送第 6 条，并在完成后生成结果。

如果只想先检查自动部分，可以停在第 5 条，生成阶段结果；这时仍未完成全部 6 条。跳过人工步骤需要填写原因，结果会明确记录跳过。

### 5. 怎样算跑通

- 总进度为 **6/6**，其中自动 **5/5**、人工 **1/1**，未跳过；3 个问题都有实际回答。
- 点击 **打开结果 Excel**，两张表分别能看到 6 行执行结果和 3 条问题回答。入门表约定回复标记为 OK1～OK4、MANUAL_OK、OK6，可人工对照；执行器保存实际原文，不自动评分。
- 点击 **打开会话备份**，查看 M0、T01 的自动记录及 H01 的人工备份。人工记录会标明来源。
- 入门 Excel 原文件仍保持输出空白；它所在目录和本轮运行目录各有一份新结果 Excel。可通过“打开运行记录”查看本轮文件。

短表通过后，再选自己的同格式测评集，校验、预览并新建一轮。无需让开发者逐条把发送内容写进脚本。正式测评需要另选正式模式，并自行核验账号初始状态。

## 按钮与状态说明

### 主窗口

| 按钮或控件 | 作用与使用时机 |
| --- | --- |
| 选择程序 / 豆包路径 | 选择本机 `Doubao.exe`。每台电脑的路径可能不同。 |
| 启动豆包 | 使用界面指定的调试端口启动豆包，供执行器连接。 |
| 检查连接 | 检查客户端、登录状态及当前账号；不会发送消息。 |
| 测试流程 | 初次用 Excel 技术回归。Excel 正式测评需核验初始状态；旧 B 两种模式和内置 4 条连通性流程为独立入口。 |
| 端口 | 默认 9223；启动与连接应使用同一端口。 |
| 当前账号 | 只读显示连接到的账号。切换账号要在豆包中操作后重新检查连接。 |
| 初始状态勾选框 | 正式测评前由使用者核验后勾选；勾选本身不会清理记忆。技术回归不要求此项。 |
| 选取/校验 | 打开 Excel 选择与预览窗口。正在运行时先暂停，等暂停完成后才能换表。 |
| 开始新一轮 / 用待运行项新建 | 使用所选流程和待运行文件建立新任务，从头发送。不会自动清理上一轮在豆包中的内容。 |
| 暂停 / 正在暂停… / 继续本轮 | 同一个按钮随状态变化。等显示已暂停后再换表；继续恢复原任务。已提交给豆包的消息不会撤回。 |
| 处理人工步骤 | 同一主按钮在 MANUAL 节点的状态，打开人工录入窗口。保存后按提示恢复自动流程。 |
| 核对后重试 | 仅在允许重试的异常状态显示。确认上一条确实未发送后才使用；已发出但仍在思考时，先核对后继续，避免重复。产品失败状态可能禁止此入口。 |
| 导出已加载对话 | 手动导出当前页面已经加载的消息；不自动翻页补全更早历史。与运行中逐条自动备份是两个入口。 |
| 打开结果 Excel | 打开本轮最新已有结果，不重新生成。没有可用结果时不可点击。 |
| 打开会话备份 | 打开本轮已有备份目录；有多个身份或来源时选择对应目录。 |
| 生成当前进度结果 | 将已保存的回复生成阶段或全流程结果；也用于结果生成失败后重试、原表目录副本失败后补存。不会重发消息。 |
| 打开运行记录 | 打开本轮目录，查看冻结输入、日志、逐条回复、备份及结果文件。 |

### Excel 预览与人工窗口

| 按钮 | 作用 |
| --- | --- |
| 选择 Excel | 选择一个本地 xlsx，尚未用于发送。 |
| 校验并预览 | 读取表格、显示顺序、会话操作、原文和错误或提示；不发送、不改原表。 |
| 用于本轮执行 | 将已通过校验的文件设为待运行输入；还需回主界面点击开始。 |
| 关闭预览 | 返回主窗口；未点击“用于本轮执行”时不更换执行输入。 |
| 保存本步并查看下一步 | 保存人工首次回复；继续处理下一人工节点或提示回主界面恢复自动流程。 |
| 记录跳过并继续 | 填写原因后记录本步跳过；不伪造成功回答。 |
| 关闭（人工窗口） | 关闭录入窗口，未保存的回复不会自动提交。 |

**“本轮”与“待运行”不同**：暂停 A 后选择 B，“本轮”仍是 A，“待运行”是 B。点“继续本轮”恢复 A；点“用待运行项新建”才从头运行 B。每轮会冻结输入，修改原 Excel 不会改变已经开始的任务。

**进度与评分不同**：进度统计已处理步骤，包含已记录的人工跳过；“执行完成”表示流程处理结束，回答是否正确需按独立问题表的评分标准另行判断。结果入口会区分阶段结果与全流程结果。

## 常见情况

- **找不到 Node.js / npm**：安装包含 npm 的 Node.js，完成后重新打开安装入口。不要只把 exe 拿到另一台电脑。
- **安装失败或没有生成 exe**：查看安装窗口的具体错误；依赖下载需要网络，窗口构建需要 .NET Framework 编译器。处理后重新运行“安装依赖.cmd”。
- **连接失败**：核对豆包路径、端口、登录状态；必要时正常退出豆包，再从执行器启动。
- **按钮灰色或正在暂停**：可能仍在执行当前操作、读取 Excel 或生成结果，等待状态更新后操作。MANUAL 节点按上面的人工步骤处理。
- **消息已发出但执行器暂停**：先核对原会话，待页面显示当前消息和回复后继续。无法确认是否已发送时不要直接重试。
- **结果少于表中总行数**：先看是阶段结果、还有人工节点，还是有回复尚未保存。不要把缺失回答当作产品得零分。
- **原 Excel 目录副本失败**：本轮运行目录里的结果保留；恢复目录可写后点击“生成当前进度结果”补存，并查看提示。

## 执行与结果

- 按步骤 ID 的数字顺序执行，按“身份 ID + 会话 ID”新建、命名或返回会话；两类消息 HISTORY/QUESTION 都从用户侧发送。
- 完整回复保存后，再按该行“回复后等待秒数”等待；暂停恢复沿用原截止时间。
- “暂停/继续本轮”为同一按钮。暂停后可选新文件，继续仍恢复当前冻结输入；“用待运行项新建”才开始新任务。
- MANUAL 节点由人工操作、粘贴首次完整回复或说明原因后跳过，不虚构平台编号，不自动换账号。
- 每条回复落盘，按会话编号更新 JSON/Markdown 备份。结束自动生成结果，也可手动生成当前进度结果。
- 原 Excel 不改动。新结果在原表同目录和本轮“测评结果”目录各存一份；可直接点“打开结果 Excel”“打开会话备份”。

本地记录在 **运行数据/**，原会话导出在 **对话导出/**。选择新文件不会清理豆包里的历史、记忆或本地记录。

## 测评集与范围

工作表名固定为“全过程执行表”“独立问题表”，第一行从 A 列起为表头，按字段名匹配，列可重排。具体字段见 [格式说明](docs/dataset-format.md)。[入门样例说明](examples/README.md)列出文件和预期现象；入门测试_6条.xlsx 与 short-flow.xlsx 内容相同。long-flow.xlsx 和 legacy/ 下旧 B 表为合成健康档案输入，均不含真实产品回答。

### 设计或转换自己的测评集

请按 [格式参考中的字段和规则](docs/dataset-format.md)制作两张工作表，保留必需字段的准确名称。可以复制入门 Excel 后修改输入内容，也可以把已有测评集转换为此格式；脚本直接读取所选文件，无需修改发送代码。

格式参考附有一段 [可复制给 AI 的辅助提示词](docs/dataset-format.md#用-ai-创建或转换测评集的提示词)。将提示词、格式参考和你的原始材料一起交给 AI，辅助生成新测评集或转换旧表。生成后先人工核对原文、顺序、会话和评分标准，再在执行器中点击“选取/校验 → 校验并预览”；确认通过后再用于本轮执行。

本版支持一个自动身份，其他身份人工处理；支持固定间隔，尚无随机间隔、多产品适配、自动评分、自动清理对话及记忆。当前已加载对话导出不保证包含尚未加载的历史；运行中逐条保存用于完整备份。

Excel 支持普通双表 xlsx（20MB、每表 10000 数据行、128 列以内）。回答和状态关联公式支持有界引用、IF、IFERROR、IFNA、INDEX、精确 MATCH；写回后核验并缓存结果。其他评分公式保留，交给表格软件重算。不能核验的回答公式明确报错；图表、图片、透视表、宏、外部工作簿链接不支持。详见 [依赖与兼容说明](docs/dependencies.md)。

## 开发验证

```powershell
npm ci --ignore-scripts
npm test
npm run check
.\构建窗口.ps1
```

测试使用模拟产品连接及临时 Excel，不向真实豆包发送。1.8.0：196 项离线检查通过，0 跳过；原生窗口在 100%/125%/150%/175%/200% 缩放下通过布局检查。真实豆包验收由使用者执行，不能把离线检查等同于完整实机验收。

代码分层：adapters（豆包 CDP）→ core（执行、恢复、归档和映射）→ tools/spreadsheets（Excel 后端）→ ui（Windows 窗口）。需求与验收由作者主导，代码实现与排查使用 AI 辅助。授权及第三方说明见 [NOTICE.md](NOTICE.md)。
