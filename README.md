# 豆包长期记忆测评执行器

面向长期记忆测评的Windows桌面自动化原型：读取结构化测评集，按步骤和会话发送原文，保存完整回复，再按问题编号生成回填结果。

基于已实测的 **V1.6.0** 整理。适合展示需求分析、自动化执行、异常恢复和数据可追溯的设计过程。

> **运行范围**：这是源码展示版。核心离线测试无需第三方包；完整Excel功能仍依赖原型使用的专用表格运行库，该库未随仓库提供，也没有公开安装步骤。本仓库不能通过一次`npm install`直接复现完整Excel流程，详见[依赖说明](docs/dependencies.md)。

## 做了什么

- 通过CDP操作豆包桌面端，执行已批准的测评流程。
- 根据“身份ID＋会话ID”新建、返回会话，并按会话编号命名。
- 区分发送确认、回答结束与测评间隔；回复结束后按表中秒数等待。
- 保存断点，支持暂停/继续；发送结果不明确时停止核对，避免盲目重发。
- 每条完整回复保存后再推进进度，按会话生成JSON/Markdown备份。
- 全过程保存所有回答，QUESTION按问题ID映射独立问题表。
- 复制原Excel后回填，原模板不改；在原表目录和运行目录各保存一份结果。
- MANUAL节点交给人工处理，记录来源或跳过原因。

## 已验证的范围

| 场景 | 原版本实测结果 |
| --- | --- |
| 6条短流程 | 5自动＋1人工已处理，3个问题回答完成回填。 |
| 66行完整表 | 60/60自动消息及回复归档，25个会话命名完成；回填60/66行、22/24问题，其余6行为人工步骤。 |

上述是原V1.6.0在专用评测账号上的执行验收，不是产品记忆评分，也不代表千条规模或所有异常都通过。仓库不包含真实账号、聊天记录或运行断点。[验收与测试说明](docs/validation.md)

## 快速检查源码

需要Node.js **22.15以上**，原验证环境使用Node.js 24。

```powershell
node --version
npm test
npm run check
```

`npm test`只运行本地模拟与纯核心测试，不访问豆包；需要专用Excel运行库或未公开模板的集成用例会明确跳过。部分核心测试使用合成预览夹具，不应把它当成Excel读写的实测证明。

## 构建Windows窗口

需要Windows及.NET Framework 4.8的C#编译器：

```powershell
.\构建窗口.ps1
```

构建后打开生成的exe，在界面选择实际豆包路径。Node从程序目录、`NODE_EXECUTABLE`环境变量或系统PATH查找；豆包路径可在界面选择，也可使用`DOUBAO_EXECUTABLE`环境变量。没有硬编码作者电脑路径。

完整Excel流程需先具备[表格依赖](docs/dependencies.md)，再选择样例、校验预览、点击“用于本轮执行”。没有该依赖时，可检查源码、运行核心测试和内置非Excel连通性流程；旧B固定模板回填也需要另行准备兼容模板。

## 代码结构

```text
adapters/              CDP连接、豆包页面操作与命名
core/                  执行、状态核对、归档、测评集校验与回填协调
datasets/              冻结的旧B合成测评流程
ui/                    Windows窗口源码
tools/spreadsheets/    原型Excel后端适配代码，不含第三方库
tests/                 模拟连接、断点与数据匹配测试
examples/              6条合成测评样例及纯核心测试夹具
docs/                  设计过程、格式、依赖与验收说明
server.mjs             窗口使用的本机服务
```
