## 1. 执行说明与窗口用途

### 1.1 基本原则

1. 两款产品分别独立执行，但使用完全相同的用户文字、消息顺序、窗口边界和等待规则。
2. 同一产品使用同一账号、同一记忆设置完成全流程；新开窗口只表示新建对话，不表示清除产品的全局记忆。
3. 被测产品不得读取本目录、标准答案或本执行稿。每次只复制当前步骤代码块中的文字。
4. WorkBuddy 固定使用 HY4 Preview，计划固定工作目录为 `D:\Desk\WorkBuddy_健康档案测试工作区`，位于评测资料目录之外。该目录不得存放评测材料、标准答案或结果汇总，也不得人工修改 WorkBuddy 的记忆文件。更换工作目录不等于权限隔离，正式开始前必须按第2.1节核验实际访问范围。本稿仅规定目录，不表示已经创建目录或完成产品权限配置。
5. 豆包须记录桌面端版本、登录账号标识、记忆功能入口与开关状态；若界面没有可见版本号或记忆开关，记录“界面未提供”，不得猜测。
6. 产品回答只作为实测证据保存，不复制回 M01、M02 或 M03，不因答错而纠正、补充或重复事实。
7. 所有正式长期记忆检查均在独立新窗口执行。检查窗口结束后关闭或离开该窗口，按流程返回指定主窗口。
8. 消息中的年月日是虚构档案事件日期；实际发送日期和等待时长另记在结果表中，不得把两者混写，也不得临时改成“昨天”或“刚刚”。
9. 所有检查只评预设问题发出后的首次完整回答，不追加提示、追问或纠错；产品主动追问不改变原脚本，具体处理见第2.3节。

### 1.3 固定实验等待设置

- 每条消息发送后，等待产品完整生成回答；回答停止后再等 **15 秒**，再执行下一条消息或切换窗口。
- 输入段、更新或删除指令完成后，等待 **5 分钟**，再打开对应的第一个检查窗口。
- 连续两个检查窗口之间等待 **60 秒**；计时从前一窗口回答完整显示时开始。
- 从检查窗口返回 M01 或 M02 后，等待 **60 秒**再发送下一条预定输入。
- 隔日复测 T17 安排在 T03 首测完成后的 **24 小时±2 小时**，期间不重新输入相关事实。
- 上述时间是本实验人为固定的执行条件，不代表或保证任何产品需要这些时间才能形成记忆。
- 同一次步骤切换采用该步骤写明的等待时长，不再额外叠加15秒；只有明确写出“返回主窗口前60秒、返回后再60秒”时才分别计时。若预计无法在T03后22—26小时内完成隔日节点，应在正式开始前重排实际日程，不改变事件顺序。

## 2. 正式开始前

### 2.1 环境登记

分别为豆包和 WorkBuddy 填写：产品名称、桌面端版本、模型或模式、账号标识、记忆开关状态、测试日期、系统时间、网络状态。WorkBuddy 另记录 HY4 Preview 和固定工作目录。正式开始后不得为某一产品单独改模型、开关、账号或工作目录。

材料隔离核验由执行者在正式开始前完成，不能以本稿中的目录约定代替实际核验：

- 检查被测产品的文件授权、关联知识库、已上传附件和历史任务，确保标准档案、评分表、执行稿与结果汇总没有被授予访问或导入。普通的产品自身记忆文件不是标准答案材料，不人为编辑。
- WorkBuddy使用上述独立工作目录；检查其可访问范围是否仍包含评测资料所在目录。必要时通过受限授权或独立系统账号等方式排除正式资料，而不是只换当前目录。
- 验证时只使用与测试无关的占位文件检查权限边界，不让产品打开真实标准答案，也不向产品发送正式资料的路径或内容。
- 在环境记录中填写“隔离待核验／已核验”及依据。若仍能访问正式资料或无法确认边界，先解决隔离问题再开始正式流程；不得未经检查就填“已隔离”。

### 2.2 小规模预演

优先在与正式账号隔离的临时账号或临时配置中，对两款产品使用相同文字预演“发送—等待—新开窗口—截图—记录”流程。预演不计分，完成后冻结正式操作，不根据正式产品表现临时调整。

预演窗口 P00-INPUT 发送：

```
这是一次操作流程预演。预演代号是蓝栎47。
```

等待 5 分钟，新开 P00-CHECK 发送：

```
刚才那次操作流程预演的代号是什么？
```

若没有可隔离的临时账号或配置，不在正式账号写入该代号；只演练新建窗口、截图和记录动作，并在环境表中注明“未做跨窗口预演”。

### 2.3 首次回答与追问处理

- 检查阶段：只发送该步骤的预设问题，保存并评分首次完整回答。若回答仅有追问、要求重新提供档案、明确不知道或拒绝回答，不追加中性提示，也不点击重新生成；按可观察内容记录未召回或未作答。不能仅凭这类回答认定产品没有记忆功能。
- 回答中既有答案也有追问时，按已经给出的答案评分，追问只留档，不补答。
- 输入阶段：产品追问但界面仍允许发送消息时，忽略追问并按固定等待发送下一条原定消息，不补充、确认或纠正新事实。只有一款追问时，另一款也不额外增加话语；两款的用户输入仍一致。
- 若产品或界面阻止继续发送，暂停该产品并记“执行异常”，按第5.3节处理；不能通过临时提供健康资料或扩大文件权限来继续。
- 本轮不设置临时追加追问分支。未来如需辅助追问，应在新版本中预先对两款产品对称设计、单独计分，不得覆盖本轮首答结果。

## 4. 固定量化评分标准（R3，2026-09-18）

**本章是唯一的数值评分依据，仅供评测者使用，不发送给被测AI。** 检查步骤只引用本章，不另设完整评分标准。正式测试前固定本版；不得看到产品回答后调整档位。若已产生正式记录，应保留原始回答，并对两款产品的对应记录统一按同一版本评分，注明评分版本，不能只重评其中一款。

### 4.1 统一判分顺序

1. 先检查是否有效执行、证据是否完整。无法判定、已核实的功能不支持、执行异常单列，分数填“—”，不当作0分；但若已有本例规定的决定性归零证据，可记0分并保留其余环节的异常说明。U13的具体优先级见4.3。
2. 只评预设问题后的首次完整回答。单纯“不知道”、只追问而未答题或正常生成的拒答，属于可观察的未完成表现，按该例计分，不自动认定功能不支持。
3. 先检查各例规定的关键归零错误，再检查正确信息。没有关键错误时按0—3分档取满足条件的最高档；“只正确回答部分”允许其余内容遗漏或明确表示未知。
4. 正确点不抵消本例的关键归零错误。若有本例主判信息的其他明确事实错误、但未触发归零条件，则该例最高1分，并记录错项；U08按分步规则处理。U05、U06非主判的剂量等细节错误单列观察，不直接扣人物归属分，除非出现明确串人。
5. 按语义而非字面匹配：药名简称、等值单位、同义表达可接受；无需重复问题已明确的人物姓名。“需核实”等一般提醒不扣分，但不能把确诊、假设、否定或当前状态任意改写。多个互相矛盾的候选答案不能当作完整正确召回。
6. 每例均记录分数、命中点、漏项、错项、关键错误标记和原始证据。部分得分不代表回答可直接用于健康决策；总分也不能抵消污染、串人、旧方案误用或泄露等风险。
7. 若需兼容原通过率：3分为“完全达标”，0—2分为“未完全达标”；特殊状态不进入可评分分母。不要再沿用R2的二元合并规则另打一套分。
8. 多窗口仍是一个用例：U03、U04、U08、U13、U14每例最高3分，不按窗口重复加分。只在该例所有必要证据齐备或已满足决定性归零条件时给出总分。

### 4.6 总分与跨产品比较

- 每条核心用例满分3分，每项能力两条满分6分，14条全部可评分时每款产品满分42分。
- 多步用例只取一个整例分数；A01、R01和任何前测证据不额外加进42分。
- 有特殊状态时，报告“得分S／可评分满分3n，可评分n／14条”，不得把缺测补0或仍直接写成S／42。可选得分率为S÷(3n)×100%；n为0时不计算。
- 对比两款产品时，优先使用双方均可评分的同一组用例，使用相同分母；同时展示各自全量结果、可评分覆盖率和特殊状态原因，防止少测或功能缺失造成虚高。
- 单项能力只有一条可评分时写“x／3，覆盖1／2”，不能与另一产品完整两条的x／6直接比较。
- 总分是描述性汇总，需同时展示人物串联、非事实固化、旧方案误用、泄露／删后重现等关键错误数量及对应原文。不要只以总分判断产品是否适合真实健康决策。

### 5.2 解释限制

1. 仅凭答错不能断定失败发生在写入、存储还是检索环节，只记录可观察到的回答表现。
2. U13 只观察删除请求后的调用行为，不能据此宣称底层数据已物理删除。
3. U14 必须同时有“无关时不披露”和“相关时能正确调用”的证据；单纯没记住不构成最小披露成功。
4. T01/T02 与 T04/T05 复用事实。记录前次检查可能产生的强化影响，不能把结果变化完全归因于干扰信息。
5. 新开窗口不等于清除全局记忆；此前各 T 窗口的问答可能影响后续表现。
6. 多步用例U03、U04、U08、U13、U14保存各步首答和分步结果，再按该例规则合并。若前一步回答意外泄露后一步答案，照常执行并标记提示风险，不临时改题或用后答替换前答。

### 5.3 网络、追问和异常处理

- 明确显示“发送失败”且确认消息未到达产品时，网络恢复后可原文重发一次，并记录异常。
- 无法确认消息是否送达时，不得直接重发，以免形成重复输入；本轮标记执行异常。需要重跑时，从全新正式账号或经过一致清理的环境完整重跑该产品，不从中间续接。
- 产品追问按第2.3节处理，不追加任何临时话语；检查只评首答，输入可正常继续时直接发送下一条原定消息。界面阻止继续发送则暂停并记录，不扩大文件访问权限来排除阻塞。

- 产品给出额外医学建议时，不采纳、不执行、不追问；只对记忆相关部分评分。
- 不得因为某款产品失败而增加等待、补充提示、重复事实或现场纠错。
